# wechat-md

[简体中文](README.md) | [English](README.en.md) | **日本語**

**WeChat公式アカウントの記事を、Codexとローカルのナレッジベースへ。**

公開されているWeChat公式アカウントの記事をMarkdownに変換し、画像をダウンロードして、出典情報とアーカイブの完了状態を記録します。単独のCLIとしても、Codex skillとしても利用できます。

[![Tests](https://github.com/passerbied/wechat-md/actions/workflows/tests.yml/badge.svg)](https://github.com/passerbied/wechat-md/actions/workflows/tests.yml)

Python 3.9+ · 実行時のサードパーティ依存なし · [MIT License](LICENSE) · 現在のバージョン: `1.1.0rc1`

## このプロジェクトを作った理由

WeChat記事をCodexに渡して、要点の整理、意見の比較、ナレッジベースへの保存を頼みたい。それでも、最初の「記事本文を取得する」段階で止まることがあります。`wechat-md`は、この実際の課題から生まれました。

本文を手作業でコピーすれば会話は続けられますが、画像、コードの書式、出典情報は別途整理が必要です。別のセッションやツールで再利用しにくいこともあります。

`wechat-md`は、この作業を繰り返し実行できるフローにします。**既知の公開記事URLを指定すると、本文と画像をローカルに抽出し、出典情報付きのファイルとして保存します。その後、Codexやほかのツールでアーカイブを利用できます。**

```text
WeChat記事URL → wechat-md → Markdown + ローカル画像 + 記事一覧
                                      ↓
                         Codexで分析 / ナレッジベースへ保存
```

Codex自体にも[ウェブ検索などの機能](https://learn.chatgpt.com/docs/codex/cli)がありますが、個別URLを読み取れるかどうかは、使用するツール、ネットワーク権限、ページのアクセス状態に左右されます。`wechat-md`はローカルで取得する方法を提供します。利用にはネットワーク接続が必要で、確認ページやアクセス制限の影響も受けます。

## 得られるもの

- **最小限のセットアップ。** スクリプトの実行に必要なのはPythonだけです。サードパーティ製Pythonパッケージ、ブラウザ、MCPサーバー、APIキー、Cookieは不要です。
- **再利用できるローカルファイル。** Markdown、画像、出典情報を自分のディレクトリに保存し、Codex、ほかのエージェント、ナレッジベース用ツールで利用できます。
- **明確なアーカイブ状態。** 完全なアーカイブ、意図的にリモート参照のままにした画像、ダウンロードできなかった画像を区別して記録します。不足している内容は出力に表示されます。
- **安全に再実行できる処理。** 同じタイトルの記事が互いに上書きされることはありません。同一記事を再処理すると記事一覧が更新され、中断または未完了のアーカイブは再取得できます。

スクリプトが担当するのは抽出とアーカイブです。要約、翻訳、リライト、画像の理解は、後続のCodexまたはほかのツールで行います。

## クイックスタート

```bash
git clone https://github.com/passerbied/wechat-md.git
cd wechat-md

# サンプルURLを実際の公開WeChat記事URLに置き換えてください
python3 wx2md.py "https://mp.weixin.qq.com/s/ARTICLE_TOKEN" -o ./archive
```

### Codex skillとして使う

[OpenAI公式ドキュメント](https://developers.openai.com/ja-JP/docs/build-skills)によると、Codexに組み込まれている`$skill-installer`を使って、ほかのリポジトリからskillをダウンロードできます。次の指示をCodexへそのまま貼り付けてください。

```text
$skill-installer https://github.com/passerbied/wechat-md から wechat-md skill をインストールしてください。インストール前に、同名のskillがすでに存在するか確認してください。存在する場合は上書きせず、現在の状態を先に報告してください。インストール後、SKILL.mdとwx2md.pyが同じskillディレクトリにあることを確認し、python3 --versionがPython 3.9以降かどうかを確認してください。Pythonが見つからない場合やバージョンが古い場合は、すぐにインストールせず、現在のOSに適したインストール方法を説明して、私の明示的な承認を得てください。Pythonが利用可能になったら、python3 wx2md.py --versionを実行してskillを検証してください。セットアップ中はWeChat記事を取得しないでください。
```

Codexは現在の環境に適したユーザー用skillディレクトリを選択します。インストール後に新しいskillが表示されない場合は、Codexを再起動してください。

手動でインストールする場合は、`SKILL.md`と`wx2md.py`を同じディレクトリに置いたまま、リポジトリ全体を1つのskillとして配置します。macOSまたはLinuxでは、リポジトリのルートからシンボリックリンクを作成できます。

```bash
mkdir -p "$HOME/.codex/skills"
ln -s "$PWD" "$HOME/.codex/skills/wechat-md"
```

リンク先に同名のskillがすでにある場合は、置き換える前に既存の内容を確認してください。Windowsでは、リポジトリを自分のskillsディレクトリにコピーし、フォルダ名を`wechat-md`にします。

インストール後は、Codexに次のように依頼できます。

> $wechat-mdでこのWeChat記事を読み、主なポイントを要約して、元のURLを残してください。

> $wechat-mdでこれらの記事を指定したナレッジベースに保存し、ダウンロードできなかった画像を教えてください。

エージェント向けの完全なワークフローは[SKILL.md](SKILL.md)を参照してください。Codexアカウントとネットワーク権限の要件は引き続き適用されます。

### 一括アーカイブとリンク検出

```bash
# urls.txtは1行に1つのURLを記述し、空行、#コメント、UTF-8 BOMに対応します
python3 wx2md.py -f urls.txt -o ./archive --delay 3

# 1つの記事本文から、参照されているほかのWeChat記事URLを抽出します
python3 wx2md.py --discover "https://mp.weixin.qq.com/s/ARTICLE_TOKEN" > urls.txt

# 本文だけを保存し、画像は意図的にリモート参照のまま残します
python3 wx2md.py "https://mp.weixin.qq.com/s/ARTICLE_TOKEN" -o ./archive --no-images
```

`--discover`が検出するのは、現在の記事本文から参照されているリンクだけです。公式アカウントの記事履歴全体は取得しません。

## 関連ツールとの選び方

各ツールは異なるワークフローに重点を置いています。既知の公開WeChat記事URLを扱い、少ない環境依存でローカルにアーカイブしたい場合は、`wechat-md`から始められます。

| ツール | 主な用途 | 選択前に確認する点 |
|---|---|---|
| **wechat-md** | 既知のWeChat記事URL → Markdown、画像、ローカルの記事一覧 | 単一のPythonスクリプト。ブラウザ操作、動画抽出、記事履歴全体の同期には対応しません |
| [baoyu-url-to-markdown](https://github.com/JimLiu/baoyu-skills/blob/main/skills/baoyu-url-to-markdown/SKILL.md) | 一般的なウェブページをMarkdown化。ブラウザによる待機やメディアのダウンロードにも対応 | Bun、関連する依存関係、Chrome/CDP環境が必要です。すでにブラウザ中心のワークフローを使っている場合や、動的ページを処理したい場合に適しています |
| [weixin-articles-mcp](https://github.com/jj-cheng25/weixin-articles-mcp#readme) | 記事本文、ネイティブ画像ブロック、動画のキーフレームをモデルへ直接返す | ブラウザは不要です。パッケージのインストールとMCP設定が必要で、動画機能にはFFmpegも必要です。公開ドキュメントはモデルへの即時入力を中心としているため、長期保存には別の保存処理が必要です |
| [wechat-article-exporter](https://github.com/wechat-article/wechat-article-exporter#readme) | 公式アカウントの記事一覧同期と複数形式への書き出しを提供していたツール | 依存していた上流の主要APIが停止したため、メンテナーは2026年7月30日に開発終了を告知しています。使用またはforkする前に、メンテナンス告知を確認してください |

この比較は、各プロジェクトが公開しているドキュメントを2026年9月15日に確認した結果に基づきます。同一環境で速度や成功率を比較したベンチマークではありません。

`wechat-md`は記事履歴の同期APIに依存せず、ユーザーが指定した記事URLだけを対象にします。公開記事ページの仕様変更には継続的な対応が必要で、すべての記事を取得できるとは限りません。

## 出力とアーカイブ状態

```text
archive/
  文章清单.csv
  <公式アカウント>/articles/<日付>-<タイトル>-<記事ID>/
    <タイトル>.md
    images/
```

CSVファイル名の`文章清单.csv`は「記事一覧」を意味します。Markdownには、タイトル、著者、公開日、出典URL、取得日時、記事ID、画像数が含まれます。画像は相対パスで参照されるため、記事ディレクトリをまとめて移動できます。

| 状態 | 意味 |
|---|---|
| `complete` | 本文と、認識されたダウンロード可能な画像をすべて保存しました |
| `remote` | `--no-images`が指定され、画像URLを意図的にリモート参照のまま残しました |
| `partial` | 本文は保存されましたが、一部の画像をローカル化できませんでした。理由は出力に表示されます |

終了コード: `0`は選択した処理が完了したか、既存の完全なアーカイブをスキップしたことを示します。`1`は失敗、部分完了、またはアクセス制限、`2`は入力エラーを示します。

**同じリストを再実行すると、未完了のアーカイブを確認して再取得できます。** 完全で変更のないローカルファイルはスキップされます。オンラインの内容を再取得する場合は`--force`を使います。以前に`--no-images`で保存した記事を、このオプションなしで再実行すると画像を追加取得します。

<details>
<summary>記事の識別、一覧の動作、旧バージョンとの互換性</summary>

- 長いURLは`__biz / mid / idx`、短いURLはパスによって記事を識別します。短いURLと長いURLは自動的に関連付けられないため、両方を指定すると同じ記事が2件保存される場合があります。
- 記事一覧はBOM付きUTF-8を使用し、記事IDごとに行を更新して、状態とMarkdown内容のSHA-256ハッシュを記録します。`--force`で同一記事を更新する場合、既存の保存先を維持します。
- 旧形式の記事一覧も読み取れます。次回の取得時に、不足している状態とハッシュを補完します。旧形式のファイルを同じ場所で更新するのは、出典が一致する場合だけです。
- 公開日はUTC+8で計算し、取得できる場合は元のタイムスタンプも保持します。文字数は本文内の漢字数と英単語数の合計で、画像URLは含みません。
- 記事ファイルと一覧はそれぞれアトミックに書き込みます。途中で失敗しても再実行できますが、古くなった画像は自動削除されません。

</details>

## CLIオプション

| オプション | 説明 |
|---|---|
| `-o, --output DIR` | 出力ディレクトリ。既定値: `./wechat-md` |
| `-f, --file FILE` | テキストファイルからURLを読み取る |
| `--no-images` | 画像URLを意図的にリモート参照のまま残す |
| `--image-workers N` | 画像の並列ダウンロード数。1〜4、既定値: 2 |
| `--delay N` | 記事間の待機秒数。最小2秒、既定値: 2。検出モードにも適用 |
| `--timeout N` | 記事と画像の1リクエストあたりのタイムアウト。既定値: 30秒 |
| `--retries N` | 一時的な失敗時の最大試行回数。初回を含め1〜5、既定値: 3 |
| `--force` | 既存の記事を再取得して更新する |
| `--no-clean` | 通常のテキストノードにあるUI由来のノイズを残す |
| `--discover` | 本文から参照されているWeChat記事URLだけを出力する |
| `--insecure` | TLS証明書の検証を無効にする。偽装された接続先へ接続する危険があるため、既定では無効 |
| `-v, --verbose` | リトライの待機とダウンロードの診断情報を表示する |
| `--version` | バージョンを表示する |

組み込みのヘルプ全体は`python3 wx2md.py --help`で確認できます。

## 対応範囲と制限

- 見出し、段落、リンク、太字、引用、ネストしたリスト、番号付きリスト、単純な表に対応します。セル結合を含む表は注記を付けて行単位に展開します。複雑な視覚レイアウトは完全には再現しません。
- コードブロックとインラインコードは個別に処理し、アスタリスクと中国語の全角スペースを保持します。スクリプト、スタイル、明示的に非表示のノードは除外します。
- PNG、JPEG、GIF、WebP画像は基本的なファイルシグネチャを検査します。この検査は画像全体のデコードを意味しません。SVG、AVIFなどの形式はリモート参照のまま残り、アーカイブ状態は`partial`になります。
- 画像をダウンロードするホストは`mmbiz.qpic.cn`、`mmbiz.qlogo.cn`、`wx.qlogo.cn`に限定します。ほかのホストの画像はリモート参照のまま残し、結果に表示します。HTMLは最大8 MiB、画像1点は最大20 MiBです。
- 音声と動画は、取得できたURL、識別子、またはプレースホルダーだけを残します。ダウンロードや文字起こしは行わず、再生も保証しません。
- Cookieの使用、ログイン、CAPTCHAの回避、非公開コンテンツやチャット履歴へのアクセス、公式アカウントの記事履歴全体の取得は行いません。

### 確認ページとレート制限

確認ページまたはHTTP 401、403、429を検出すると、そのバッチを停止します。アーカイブモードでは残りのURLを`待处理链接.txt`（「処理待ちリンク」）へ書き出し、検出モードでは標準エラー出力へ送ります。画像ワーカーがすでに開始したリクエストは完了する場合があります。連続した再試行は避け、追加の根拠なしに送信元IPが原因だと判断しないでください。

### 出力ディレクトリがロックされている場合

1つの出力ディレクトリへ同時に書き込めるCLIプロセスは1つだけです。プロセスが強制終了した場合は、ほかのプロセスがそのディレクトリを使用していないことを確認してから、残っている`.wx2md.lock`を削除してください。

### サーバーへのデプロイ

現在のリリースは、ローカルCLIとエージェントのワークフローを対象としています。マルチテナントのネットワークサービスとして運用するためのセキュリティ検証は行っていません。TLS検証は既定で有効です。入力URL、リダイレクト先、最終URLについて、許可されたスキームとホストを確認します。

## テストとコントリビューション

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile wx2md.py
```

56件のテストで、変換の忠実性、アーカイブの復旧、画像の状態、リダイレクト制限、CLIの動作を検証しています。合成HTML、モック化したネットワーク応答、一時ディレクトリを使うため、WeChatには接続しません。

[クロスプラットフォームCI](https://github.com/passerbied/wechat-md/actions/runs/34968971941)は、LinuxのPython 3.9、3.12、3.14、およびmacOSとWindowsのPython 3.12で成功しています。Windowsでは`tzset`に依存するタイムゾーン切り替えテストをスキップします。CIではオフラインテストと構文チェックを実行します。

2026年9月15日には、macOS上で1件の公開記事を使った実機確認も行いました。本文と5/5点の画像を保存し、すべての画像とGIFフレームを別のデコーダーで検証し、再実行時に完全なアーカイブが正しくスキップされることを確認しています。この1件の結果だけで、すべての記事やネットワーク環境との互換性を保証することはできません。

不具合報告とコントリビューションは[Issues](https://github.com/passerbied/wechat-md/issues)で受け付けています。可能であれば、実行環境、エラー出力、再現可能なページ構造を添えてください。Cookie、個人情報、共有する権限のない記事全文は投稿しないでください。
